Create a work item (queued). Idempotent when --idempotency-key is passed: a repeat returns the existing item and writes nothing

Usage: chaperone work create [OPTIONS] --title <TITLE>

Options:
      --db <DB>
          Path to the ledger (defaults to chaperone/ledger.db in the user data dir)
      --title <TITLE>
          
      --format <FORMAT>
          Output format: json is one {ok, data, meta} object; jsonl is one item per line followed by a trailer that is the only line with an `ok` key [default: json] [possible values: json, jsonl]
      --source <SOURCE>
          linear | github | note | issue | manual (default manual)
      --source-id <SOURCE_ID>
          CORE-123 for linear, owner/repo#N for github, PER-12 for issue, an id for note; stored as given
      --repo <REPO>
          The repo the work happens in, stored as given
      --next-action <NEXT_ACTION>
          
      --idempotency-key <IDEMPOTENCY_KEY>
          
      --spec <SPEC>
          The spec this item is a slice of (its id or parent key)
      --lane <LANE>
          The lane it runs in, e.g. CORE-4040:B (one herdr workspace)
      --lane-pos <LANE_POS>
          Its order in the lane (a stack's layer)
      --kind <KIND>
          What the lane delivers; picks the route at the first claim [default: code] [possible values: code, docs, measure, investigation]
      --pr-flow <PR_FLOW>
          How it lands: through a PR, direct, or none (no PR at all) [default: pr] [possible values: pr, direct, none]
      --dry-run
          Run the real write and roll it back; meta.dry_run is true
      --agent <AGENT>
          Your agent name, [a-z0-9._-]{1,40} (default: $DAISY_AGENT)
      --session <SESSION>
          Your session id, [A-Za-z0-9._:-]{1,120} (default: $DAISY_SESSION)
  -h, --help
          Print help
