Waive a check the harness runs for a lane that cannot pass it now: the plan check of a lane that coded before its plan was attacked, or the size cap of a lane whose change only makes sense whole. The lane writes its own plan waiver only when the check cannot run (the head's harness diff changes code, or its plan sessions used plan_attempts with no answer) and its size reason (no --lines); the owner can overturn either. rounds, and --lines, are the owner's

Usage: chaperone check waive [OPTIONS] --work <WORK> --reason <REASON> <KIND>

Arguments:
  <KIND>
          Possible values:
          - plan:   The plan check, on the commit the lane is on (none before v20)
          - size:   The `code_lines` cap, raised to --lines for this lane alone (v20's gate reads it)
          - rounds: The `review_rounds` cap on fresh reviews, raised to --rounds for this lane alone (v21 on)

Options:
      --db <DB>
          Path to the ledger (defaults to chaperone/ledger.db in the user data dir)

      --work <WORK>
          

      --format <FORMAT>
          Output format: json is one {ok, data, meta} object; jsonl is one item per line followed by a trailer that is the only line with an `ok` key
          
          [default: json]
          [possible values: json, jsonl]

      --lines <LINES>
          For size only: the lane's raised `code_lines` limit, the owner's (v20's gate reads it); the lane's own size reason has none

      --rounds <ROUNDS>
          For rounds only, and required there: the lane's raised `review_rounds` limit

      --reason <REASON>
          Why; one line, kept on the event and redacted at write

      --agent <AGENT>
          Your agent name, [a-z0-9._-]{1,40} (default: $DAISY_AGENT)

      --session <SESSION>
          Your session id, [A-Za-z0-9._:-]{1,120} (default: $DAISY_SESSION)

  -h, --help
          Print help (see a summary with '-h')
