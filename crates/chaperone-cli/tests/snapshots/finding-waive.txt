Stop an open, verified or disputed finding blocking, or (scope only) release an accepted plan finding: the owner's, or a fresh agent's (--kind). The lane itself only defers (--kind deferred, with --ref the repo rule or follow-up issue) an open or verified review finding it cannot fix in the lane, never one titled owner: or overturned. Never waive a finding where a gate fails open on a path a lane can reach: fix it or ask the owner

Usage: chaperone finding waive [OPTIONS] --reason <REASON> --kind <KIND> <EVENT> <KEY>

Arguments:
  <EVENT>  The event id of the check.finished that raised it (`work events`)
  <KEY>    The finding's key in that check (its id in `reviews get`)

Options:
      --db <DB>            Path to the ledger (defaults to chaperone/ledger.db in the user data dir)
      --reason <REASON>    Why; kept on the event and redacted at write
      --dry-run            Run the real write and roll it back; meta.dry_run is true
      --format <FORMAT>    Output format: json is one {ok, data, meta} object; jsonl is one item per line followed by a trailer that is the only line with an `ok` key [default: json] [possible values: json, jsonl]
      --agent <AGENT>      Your agent name, [a-z0-9._-]{1,40} (default: $DAISY_AGENT)
      --session <SESSION>  Your session id, [A-Za-z0-9._:-]{1,120} (default: $DAISY_SESSION)
      --kind <KIND>        fixed and disproved need --ref. scope, deferred and accepted are countersigned: written by a fresh session, one with no event on the lane but its own such waivers; or deferred by the lane, with --ref [possible values: fixed, disproved, scope, deferred, accepted]
      --ref <REF>          The commit and test, the file:line, the owner text or the follow-up issue; one line of at most 500 characters
  -h, --help               Print help
