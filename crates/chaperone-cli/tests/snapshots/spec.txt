The dispatch spec of a parent issue, versioned. /dispatch writes it, /issue and /ship read it

Usage: chaperone spec [OPTIONS] <COMMAND>

Commands:
  create   Create the spec for a parent, at version 1 (draft). One per parent: a second create is refused and names the spec to update
  get      A spec with its slices and decisions parsed from the body. With --key, that slice alone: its section, its decisions and the spec-wide ones, and its siblings with their work item status and PR. --key without a spec finds the spec that has the slice
  list     Every spec at its newest version, most recently changed first
  update   Append a new version
  approve  Mark the spec approved (draft -> approved); approving again is a no-op
  decide   Record a decision: one line appended to `## decisions` as a new version, `- [slice N] Q: ... A: ... (agreed: <where>, <date>)`. Without --slice or --key it is spec-wide
  help     Print this message or the help of the given subcommand(s)

Options:
      --db <DB>          Path to the ledger (defaults to chaperone/ledger.db in the user data dir)
      --format <FORMAT>  Output format: json is one {ok, data, meta} object; jsonl is one item per line followed by a trailer that is the only line with an `ok` key [default: json] [possible values: json, jsonl]
  -h, --help             Print help
